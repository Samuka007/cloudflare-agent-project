# 内核子系统分解（kernel-subsystems）

**定位**：架构总索引。以 OS 级设计方法论分解——**状态单一所有权、机制与策略分离、接口窄契约、失败域隔离、依赖方向无环、预算随设计走**——每个子系统登记六个字段：职责／状态所有权／接口与消费方／不变量／失败语义／预算。子系统边界从接缝推导（状态所有权缝、失败域缝、依赖方向），不从分类学推导。

**分解方法**（先说清怎么切的，边界本身待用户确认）：
1. **状态所有权缝**：每份可变状态有且仅有一个拥有者（single-writer）；所有权边界即子系统边界。thread 事件日志归进程子系统、压缩游标归内存管理、provider 会话句柄归 I/O 栈——各自不可被外部直接写。
2. **失败域缝**：崩溃/超时/驱逐的波及半径。DO 驱逐、provider 断流、daemon 离线是三个独立失败域，不得让一个失败域的恢复逻辑散进另一个的代码。
3. **依赖方向**：装配 → 调度 → I/O 栈 →（进程/内存/系统调用/VFS/IPC/中断 横切）。无环；下层不得感知上层存在（I/O 栈不知道装配的存在）。
4. **机制与策略分离**：子系统只提供机制（如"压缩在阈值触发"），策略（阈值多少、保什么）是配置/裁决，不进机制代码。

## 内核核心与结论

**内核核心 = 2+9+10（+1/8 的级联/中断半边）**——三个设计空洞全部落在循环本体，这是"对核心没把握"的实体。外围（3-8）已按两源纪律设计。

**横切纪律**：任何跨子系统调用必须走表中接口列；绕接口直接摸他子系统状态=违规（lintable：import 方向检查）。

**安全/权限**非内核子系统，独立轨道（#55-57）。

**维护**：子系统增删/字段变化时更新此表；wayfinder 内核图驱动空洞补齐。
