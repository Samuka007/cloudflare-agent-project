## 3. 配置变更语义

- **edge 用户面 = 热生效（#362）**：D1 `provider_configs` 行经面板/API 写入 → 下一次请求的读面（execution-options / projections / CRUD list）即见；turn dispatch 走 overlay 内容指纹（`loadProviderConfigOverlay` → `RelayProviderRegistry.applyOverlay`，实例缓存清除——key 轮换/baseUrl 编辑不留 stale wire client）；AgentDO driveTurn 回合边界 best-effort `refreshRuntime`（失败续用 last-known 注册，配置读永不绝杀 turn）。
- **产图源 seat = 热生效（#448）**：seat 读折进同一 overlay 内容指纹（provider 行 + seat 单批双 SELECT——回合边界 refresh 链上多一次独立 await 会翻转 L1 send→read 竞态的 DO 事件循环节拍，实测单批化后与基线一致）；PUT 后 `config-changed` 广播与 provider 行写同路。
- **实验闸 seat = 热生效（#502）**：三闸行折进与产图源 seat 同一 overlay 内容指纹（loader 单批第 4 条 SELECT——单批纪律同 #448；翻转即指纹变，`ComposedAgentDO.refreshProviderOverlay` 经 `applyToolCapabilities` 于回合边界应用）；PUT 后 `config-changed` 广播与产图源写同路；行缺省=全 off（omp 姿态），删行即回缺省；`GET/PUT /system/tool-capabilities` 为写/读面，`GET /system/config` 的 `featureFlags.toolCapabilities` 为客户端投影。
- **edge 部署通道 = 退役（#500；#534 模型域换 pi 正本）**：部署通道 env 标量族（relay base/key/model/maxTokens/contextWindow/thinking budget/image input、machine pin、权限模式）全删——API_KEY/BASE_URL 随通道死（#450 D1 加密列已是唯一凭据正本）；窗口/图像输入归 D1 行字段（`contextWindow`/`input`，面板写即热生效）；**推理域=pi 形状（#534，用户裁决 2026-10-08）**：行字段 `reasoning: boolean` + `thinking?: { mode, efforts, defaultLevel?, effortMap?, effortRouting?, effortBudgets?, requiresEffort? }`（@oh-my-pi/pi-catalog/model-thinking 直引，npm 精确 pin）——`thinkingBudgetTokens` 一字段三职（能力门/阶梯驱动/装饰数）退役，4096 是旧 HARNESS_DEFAULTS 化石；存量行经 schema 兼容读自动迁移（数字→effortBudgets wire 细节，阶梯→efforts），写面存储即归一化；**权限模式默认归 D1 `permission_mode` 单行 seat**（`GET/PUT /api/v1/system/permission-mode`，行缺省=`full`；server 桥逐命令读取，写面生效无需重部署）；machine 绑定=cloud 占位常量（#377）。dispatch 侧不再读任何部署 env：`RelayProviderRegistry.create(overlay)` 纯 D1；wire 安全兜底标量（maxTokens 8192 / contextWindow 200K）仅在行未声明时生效，不影响路由。`POST /system/config/reload` 仍是刻意 no-op。pre-#351 老 journal 线程零迁移（剥物化裁决）：下次 send 即 422 `selection_missing`（fail-closed），选择经 #499 picker 显式恢复。
- **daemon 侧 = 拓扑/凭据 env 保留，provider/judge 配置零 env（#523）**：daemon env 面仅剩 `DAEMON_TASK_ISOLATION`（#110 隔离后端）、enroll 凭据（`DAEMON_ENROLL_KEY`/`DAEMON_JOIN_CODE`）与 CF Access 服务令牌对（#420）——agent-auth env 通道已整删，宿主零模型注册表；改判相模型=面板改线程 pinned selection（D1 正本，热生效），无需重启 daemon。

投影端点与 SPA 节的零秘密值断言由 L1 钉死：`apps/server-worker/test/compat/system-provider-projections.test.ts`「never emits secret values」用例注入假 key（relay/brave/searxng）后对序列化响应断言 `not.toContain`。#362 扩展：`apps/server-worker/test/compat/system-provider-configs.test.ts` 对三个投影面（providers CRUD / execution-options / provider-projections）注入带 key 行后断言零明文，并直读 D1 断言 `api_key_enc` 列无明文且经 master key 可解（AES-GCM roundtrip + fresh IV 可观察轮换）；无 master key 的部署拒绝明文 key 写入（路由 422 `master_key_missing` + db 层 backstop）。#364 扩展：`apps/server-worker/test/compat/system-provider-import.test.ts` 对导入面断言同链（粘贴 key 直读 D1 无明文 + rig key 可解 + 判词/列表零明文回显），`apps/provider-app/test/models-yml-import.test.ts` 钉解析/映射语义（omp 词汇表、thinking 遗留区间归一、#350 zod 重校验）。新增 provider 配置点进本表时，必须同步回答两问：投影面是否需要它？需要则只加存在性 boolean，永不透传值。
